DevOps ::::

	DevOps is a Software Development Strategy/Process, used to promote the collaboration between the teams like Development & Operations Team to achieve - Continuous Development, Continuous Integration, Continuous Testing, Continuous Delivery, Continuous Deployment and Continuous Monitoring in more automated fashion.

	- Application Architecture :::
	
		- Monolith Application Architecture	
			- Tightly Coupled Application Architecture
			- All the Functions/Modules are tightly coupled
			- With this we can achieve Continuous Delivery. But, we cannot achieve Continuous Deployment.
		

		- Micro-Service Based Application Architecture
			- Loosely coupled Application Architecture
			- Here, each and every function / Module are called a Micro-Service
			- Each Micro-Service can be idependently developed, tested and implemented to production.
			- With this we can achieve Continuous Deployment

	- Stages of DevOps :::
	
		- Continuous Development ::::
		
			- It is the capability of the Development Team to Continuously Develop the Source Code Changes.
			- On DevOps perspective - It is used to improve the Developers' productivity.
			
			
		Developers : 

			Role of Developers ?
			
				- Understand the Requirement/Design Docs and Develop the Application				
				
				- Create Source Code 
				- Build the Source Code 
						(Process - to compile the source code and create artifacts(binaries - *.war/*.jar/*.exec/*.dll))
				- Unit Testing 
				- Promote the Changes to Test Environment
				- Notify the Testing Team thru Email
				
				Using DevOps Process:
				
					- Create Source Code 
					- Save the Source Code in the Source Code Repositories(GITHub)
				
				Automate: 

					- Build the Source Code 
							(Process - to compile the source code and create artifacts(binaries - *.war/*.jar/*.exec/*.dll))
					- Unit Testing 
					- Promote the Changes to Test Environment
					- Notify the Testing Team thru Email
					
			Tools:
			
				- IDE - Integrated Development Environment - Eclipse / Visual Studio Code / Visual Studio / Pycharm
				- Git 	
				- GitHub 
				- Build Tools, Unit Testing Tools 
		
		
		- Continuous Integration :::
		
			- It is the capability of the Development Team to Continuously Integrate the Source Code Changes to High Environment for further testing.		
		
				Automate:

							(Process - to compile the source code and create artifacts(binaries - *.war/*.jar/*.exec/*.dll))

			- It is the capability of the Testing Team to Continuously Test the Source Code Changes
			- Generate the Test Data, Test Scenarios
			
			
			Tools:
			
				- Testing Tools - Selenium,TestNG,Junit
				- Jenkins - To enable Test Automation and notification			
		
		
		- Continuous Delivery/Deployment :::
		
			- Continuous Delivery ::		
				- It is a process to release the changes to production environment with manual reviews & approvals
				- This leads to Downtime.
				- During the application upgrade / downgrade, we experience Application Downtime.
				- This is used for Monolith Application Architecture.
		
				- CI/Cd(Delivery)
				it is automating the integration and delivery/deployment of the applications.

			Eg.: 
			
				- Online Banking Services/Insurance Applications/Logistic Managements/ : ==> Core Legacy Applications
				
					-> Deployment Window --> 4Hrs - 6Hrs. --> 
					
						Current_Version : v1.1 		===>  New_Version : 2.0
						
							-> Fix the Issue / Revert the Changes 
							
			- Continuous Deployment ::
				- It is a process to release the changes to production environment without any manual reviews & approvals
				- During the application upgrade / downgrade, There is no Downtime
				- Zero Down Time can be achieved only with the Micro-Service Based Application Architecture
				- This is Considered as the Matured Level of DevOps.

				- CI/CD(Deployment)				

			Eg.: 
			
				Netflix/Facebook/Amazon(E_Commerce)/Prime ->>>>
